# Tree 维护宪法

## Tree 是什么

Tree 是属于用户自己的本地个人上下文库（Markdown 文件夹 + Git 版本历史），独立于任何单一 AI 工具、模型或平台，由所有接入的 AI 共同读取和维护。

不同工具通常只能看到用户的局部片段（写代码工具只见代码，消费与饮食工具只见日常订单，运动工具只见身体数据，笔记与社区工具只见阅读收藏）。Tree 负责把散落在各处的、关于「这个人」的真实信息拼合起来——包括他是谁、怎么想、在做什么、怎么做事、怎么生活。

- **入树总标准**：凡是模型原本不知道、关于这个人的真实信息，只要未来跨时间或换另一个 AI 协作时可能用得上，就属于 Tree 的范围；不属于“人”本身的工程实现细节、公开常识与外部交付成品留在外部。
- **完全开放演化**：Tree 里没有焊死的模板。具体页面、子目录、一级主干（默认 `01~04`）乃至本 `README.md` 本身，都允许 AI 根据用户的真实生活与工作场景随时新增、修改、删除和重组。
- **效力**：本文件是所有 AI 维护 Tree 时的唯一内容契约，任何写入、修改或删除动作前都必须先完整读取本文件。若文末定制区有树主人手写条款，优先级高于本文件一切默认规则。

## 一、记什么、谁能改（入树判断与写权分级）

### 1. 入树判断：宁可多记，不漏真知
- **少记不如多记**：少记是不可逆的信息丢失，多记只是可逆的临时冗余（后续有自然衰减与定期修剪负责合并清理）。对照 Tree 的定位与现有目录自主判断：个人判断与立场、私有事实、饮食运动与生活习惯、人际与协作细节、选择与否决理由、对 AI 的纠偏、筛选消化过的专题知识等均可入树。内容值不值得记拿不准时，先记下来；放到哪个目录或与旧记录冲突拿不准时，先问用户再落盘。
- **跨工具主动补齐**：如果当前 AI 能访问其他 AI 看不到的个人数据源（如办公文档、笔记收藏、电商外卖、生鲜买菜、运动健康等），在初始化或日常协作中，应主动把从中看出来的稳定习惯、外部入口线索，以及后续其他 AI 也用得上的客观日常记录（如饮食、运动情况）沉淀进对应主题页，让没有这些权限的 AI 也能接力。这类持续增加的日常记录按周或按月合写在同一页，**严禁按天新建零散文件**。
- **明确排除两类内容**：
  1. 毫无信息量的寒暄、一次性临时查询、临时报错粘贴，以及大模型已知的公开常识；
  2. 代码仓库内部的工程实现细节（具体文件名、函数/类名、前端 DOM 选择器、接口字段、端口号、单测与排错过程——这些属于代码仓本地开发文档，留在外部工作区）以及给他人交付的成品报告、未经消化的外部长文原文。

### 2. 写权分级（直接执行 / 先向用户确认）
- **直接执行**（完成后用 1 句话告知路径与改动摘要，不打断对话）：
  - 用户亲口要求记住、新增、修改或调整结构的事项（含用户明确要求修改核心身份页或目录结构）；
  - 用户对 AI 的明确纠偏、沟通偏好或做事规矩更新；
  - 新增归属清晰的个人思考或外部专题摘编，更新已有在推事项的进展或已拍板结论，常规页面重命名与移动，以及已有明确落点的周期性日常记录。
- **先向用户确认再执行**（仅限用户未明确发话、由 AI 自行推断提议时）：
  - 提议调整一级主干结构、修改本 `README.md`，或由 AI 自行推断去新建/改动核心身份页（基本档案、价值观、长期目标）；
  - 改动用户打上 `#note` 标签的手写原稿（平时直接读取、建立 `[[双链]]` 或提炼结论写入旁页，不擅自改写原文）；
  - 新建一个长期项目，或删除实质内容页（删除前须先排查全库反向 `[[双链]]` 引用）；
  - 推翻已有旧结论、处理不同页面间的说法冲突，或执行首次历史数据批量迁移；
  - 目录归属模糊、事实依据不足，或涉及高敏隐私明细（如具体病历、金融账户明细）。

## 二、放哪里（默认骨架与分类边界）

### 1. 默认起步骨架（按需生长，不建空目录）
`01~04` 是开箱起步的默认一级主干，不是固定模具。当现有主干装不下用户的真实场景时（例如需要新增 `05-客户档案/`、`投资与财务/`、`家庭与健康/`，或合并、重命名现有主干），可按用户要求灵活调整，并同步更新本文件及相关 `[[双链]]`。下方子分类均为常见参考词表，用到时再建，**绝不预建空文件夹**。

| 默认主干 | 常见子分类示例（按需建） | 承载内容 | 默认加载方式 |
| :--- | :--- | :--- | :--- |
| `01-关于我/` | 基本信息、价值观、长期目标、习惯偏好、设备与资产 | 我是谁：身份档案、重要关系、人生信条、3~5 年长期方向；饮食运动作息喜好、产品品味、软硬件与外部知识库/工具入口 | 仅少数核心底色设 `always: true`，其余按需 |
| `02-我的思考/` | 观点与认知、灵感与点子、随笔与反思、问题与困惑 | 我怎么想：对外规律判断与方法论、按主题编译互链的书课/行业专题（`<专题>/INDEX.md`）、未动工想法、向内复盘随感、尚未想通的真问题 | 按需加载 |
| `03-我正在做的事/` | 工作、学习、生活 | 我在干什么：实际推进中的项目（长期项目建 `<项目名>/项目总览.md` 并标 `location`）、在学课程训练、阶段生活大事与周期记录 | 按当前工作区、话题或近期热度自动唤起 |
| `04-我如何工作/` | 工作原则、沟通与表达、流程与标准、工作习惯、工具使用 | 我怎么做事：跨项目通用原则、沟通文风要求、具体流程、个人定制 Skill（`<skill>/SKILL.md`）、专注复盘节奏与工具分工红线 | 仅核心原则设 `always: true`，其余按需 |

> 隔离目录说明：`outputs/`（如每日简报 `outputs/daily/`）与 `.tree/`（运行配置、变更记录与临时暂存区）用于存放衍生消费产物与运行状态，不放个人慢变量正文。

### 2. 容易混淆时的四条判断线
1. **只在想 vs 已经在做（`02` vs `03`）**：还停在脑子里的想法放 `02`；已有实际推进动作的放 `03`。不要把近期高频做的具体项目自行拔高或脑补成 `01` 的长期人生目标——长期方向仅在用户亲口确认时记录。
2. **向外看规律 vs 向内看自己（`02` 内部）**：对外部世界、行业规律与阅读消化的判断放 `观点与认知`；向内审视的个人经历复盘、情绪与随感放 `随笔与反思`。
3. **客观事实 vs 做事规矩（`01` vs `04`）**：个人生活喜好、作息现状、拥有哪些设备与外部账号入口放 `01`；干活准则、文风禁区、专注节奏与工具操作约束放 `04`。
4. **个人规矩 vs 通用工具说明**：通用工具怎么调接口留给宿主客户端自身的 Skill 目录；`04` 只沉淀属于用户个人的做事规矩与个人工作流。

### 3. 同主题聚拢与来源区分（本人判断 vs 外部参考）
- **同一主题聚在一处，用 `origin` 和 `source` 分清是谁说的**：同一主题下的个人判断与外部精选资料（书课笔记、深度文章、行业案例）统一收进对应主题目录，像维护 Wiki 一样互链组织，不要按“外部导入”另建平行目录把同一主题拆成两半：
  - 用户本人的事实或判断：默认 `origin: self`；
  - 纯外部资料整理或客观摘编：标 `origin: external` 并填明 `source: "<URL、书课或平台出处>"`，**严禁把外部观点当成用户本人的定论**；
  - 既有外部材料又包含用户内化批注：标 `origin: mixed`，填明 `source`，并在正文中分清“我的判断”与“外部参考”。
- **`03` 项目页站在主人视角表达**：重点写清为什么做与核心价值、已经做成什么、核心拍板与否决过的方案、接下来做什么、沉淀的教训，以及外部工作区路径 `location`，不把代码模块说明书搬进来。

## 三、怎么写（文件组织、正文写法与元数据）

### 1. 目录与文件生长规则（先查重、先单页、后建专题）
- **原地更新优先，不建碎片页**：动笔前先浏览现有目录与相关页面，能融进已有专页的直接更新原页；禁止新建 `xxx补充.md`、`xxx其他.md`、`xxx方案1.md`、`xxx最新.md`、`2026-11-26.md` 等临时碎片文件；**禁止在任何子目录下建 `README.md` 写正文**（专题索引统一命名为 `INDEX.md`）。
- **总路径深度不超过 4 层**（最多 3 级文件夹 + 文件名，如 `03-我正在做的事/工作/某项目/项目总览.md`）。
- **单页起步，内容多了再升格为专题目录**：除长期项目（`<项目名>/项目总览.md`）与个人 Skill（`<skill>/SKILL.md`）外，新话题一律先建单个 `.md` 文件；仅当同一主题自然长到 **3 篇及以上**，或单页超过约 **300 行且子话题明显分叉**时，再升级为 `<专题>/INDEX.md` + 互链子页（同步更新全库关联 `[[双链]]`；含 `INDEX.md` 且满 3 篇的子目录在全景目录中会自动折叠为一行）。
- **同名页面 `[[双链]]` 带父目录消歧**：跨目录引用 `项目总览.md`、`INDEX.md` 等重名专页时，必须写成 `[[项目A/项目总览]]`、`[[经济学/INDEX]]`，不要裸写 `[[项目总览]]` 或 `[[INDEX]]`。

### 2. 正文写法：只留最新现状，保留否决记录
- **每页只维护最新现状，历史演变交给 Git**：事实或结论变化时，必须先通读整页再原地改写对应段落，**严禁直接在文末追加一条相反更正却把过时结论留在上面**（文末追加仅适用于新增周期记录或全新独立条目）。
- **保留已否决的方案与原因**：把明确排除过的方案和放弃原因留下来，防止日后 AI 反复提议已经否掉的老路。
- **标准页面结构与示例**：正文第一行写 `# 标题`，第二行用引用块写 `> 适用时机：<什么场景下读本页>；<一句话核心结论>`（中间务必用分号 `；` 隔开，分号后半句直接作为目录摘要，不写“本页介绍了……”）；正文用第一人称或客观大白话写清背景、结论与时间锚点（如 `2026.11`），禁止写“用户在对话中提到……”这类旁观记账腔。

```markdown
---
updated: 2026-11-26
always: false
status: active
origin: self
---

# 对外写作与汇报原则

> 适用时机：起草文章、述职材料或替我润色对外文案时读取；核心是先亮可反驳的判断，靠具体事实和数字说话，不用自造黑话与煽情排比。

## 一、核心规矩
- 开篇直接给结论和取舍理由（2026.11 确立），不铺垫空洞背景。
- 封面标题直接写清「谁的 + 什么汇报 + 哪一年」，让受众 2 秒看懂。

## 二、已否决做法
- 不再用谐音双关或悬念式大标题——实测受众抓不住重点，沟通成本高。
```

### 3. Metadata 字段与唤醒约束
- `updated: YYYY-MM-DD`：页面最后更新日期，每次修改正文时同步刷新为当天日期。
- `always: false`：是否每次对话无条件常驻注入。全库默认 `false`；仅全场景通用的核心身份与铁律设 `true`，建议全库不超过 5 篇，且每篇有效非空正文**不超过 45 行**（超出部分会被截断）。不要手写静态的 `当前聚焦.md`，近期活跃焦点根据更新时间与读写热度自动生成。
- `status: active`：页面状态，可选 `active`（默认）| `paused` | `archived` | `superseded`。非 `active` 或超过 90 天未更新的按需页自动退居后台，仍可通过搜索召回，再次更新即恢复活跃。
- `origin: self` 与 `source: ""`：真值来源（`self` | `external` | `mixed`）；`external` 或 `mixed` 时 `source` 必填出处 URL、书课或平台名。
- `kind: project` 与 `location: ~/Work/my-app`：`03` 可选字段（`kind` 可选 `project` | `idea`；`location` 关联本地目录或链接，进入该目录时自动锚定唤起）。
- `when: "Dockerfile, 马拉松训练"`：可选精准触发条件。**一旦填写 `when:`，自动对焦将优先匹配 `when:` 而不再使用正文的 `> 适用时机：`**，因此非必要留空；填写时只写高区分度专词或特征文件名，严禁写 `AI`、`产品`、`工作`、`work`、`python`、`思考`、`文档` 等泛词。

## 四、认知诚实、安全底线与定期修剪

1. **分清四类认知状态，不脑补**：严格区分「用户已确认的事实」「外部或他人说法」「AI 的观察推测」「尚未决定的疑问」。工具输出不等于用户认同；未想通的真问题放进 `02/问题与困惑`；素材不足时先问用户，不要把推测写成既定事实。整理专题遇到资料观点冲突时，在页面与 `INDEX.md` 中并列注明各自立场与出处，不擅自抹平。
2. **安全与隐私红线**：个人生活、饮食健康、运动、财务规划等真实个人上下文均可按需记录；但**严禁写入任何明文密码、API Key、Token、Cookie、私钥等安全凭证**。涉及第三方的敏感隐私（如他人身份证号、私密病历等），未经用户明确要求不入树。
3. **定期修剪与沉淀归档**：
   - 定期清理过期或低价值临时记录，合并意思重复的短页，修复断链与未被索引引用的孤儿页，把反复纠偏过的偏好固化进 `04`；发现跨页说法矛盾时先向用户确认再统一修改。
   - 事项流转：已动工的想法从 `02` 移入 `03`；事项完结或搁置后，把验证过的通用认知沉淀回 `02`、可复用方法沉淀回 `04`、真正上升为长期人生方向的经用户确认后更新至 `01`，原事项页标为 `status: archived` 归档留存。
