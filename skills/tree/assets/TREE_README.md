# Tree —— 个人上下文系统（Personal Context OS）

> **模型和算力属于大厂，但上下文属于你自己。**
> Tree 是本地拥有、人机共治的个人维基与上下文库（Git-backed Markdown），只沉淀模型不知道的“关于你的真实信息”，让任何 AI 按需挂载、第一秒就懂你。

> **显式契约**：本文件既是系统地图，也是所有 AI Agent 维护 Tree 时**必须首先读取并严格遵守的唯一维护准则**。修改本文件即直接改变 AI 组织与维护这棵树的方式。

## 一、结构与路由地图（单一尺度 + 按需加载）

> **默认而非写死**：`01~04` 为默认一级主干，各分支下的子分类是给 AI 的默认路由词表。未经用户允许，AI 不得擅自增删或重命名一级主干；调整后必须同步更新本 `README.md`、`.tree/config.json`、`INDEX.md` 及受影响页面的路径与 `[[双链]]`。

### 1. 目录全景与 L0 加载策略

Tree 按 **「我是谁 vs 我怎么想 vs 我在干什么 vs 我怎么做事」** 切分主干，并把外部输入（`seed/`）与快变量产出（`outputs/`）隔离在主干之外，结合 **`always: true | false`** 实现「一条信息只有一个家」：

| 目录 | 推荐子分类 / 区域 | 放什么（具体内容） | L0 加载策略 |
| :--- | :--- | :--- | :--- |
| **`01-关于我/`**<br>*我是谁（客观底色）* | **`基本信息`** | 姓名、性别、年龄、城市、职业背景、身高体重、家庭情况及核心人际关系（伴侣/合伙人/关键同事等） | 常驻（`always: true`） |
| | **`价值观`** | 我相信什么、最看重什么、做人做事的底线 | 常驻（`always: true`） |
| | **`长期目标`** | 人生梦想、3~5 年职业与人生大方向、长期愿景（不含短期或当前在推的具体项目） | 常驻（`always: true`） |
| | **`习惯偏好`** | 饮食忌口、睡眠作息、运动习惯、审美与消费偏好、常看的信息源 | 按需（`always: false`） |
| | **`设备与资产`** | 电脑/手机硬件、常用软件清单、服务器、域名与重要线上资产 | 按需（`always: false`） |
| **`02-我的思考/`**<br>*我怎么想（认知资产）* | **`观点与认知`** | 向外看事：对行业、产品、商业、世界想明白的看法与规律（含消化后的阅读结论 + 出处链接） | 按需 |
| | **`灵感与点子`** | 向未来试：还没动手干的产品创意、副业脑洞、文章选题（一旦开干转入 `03`） | 按需 |
| | **`随笔与反思`** | 向内看己：个人经历复盘、阶段总结、日常感悟与日记（人类手写标 `#note` 只读保护） | 按需 |
| | **`问题与困惑`** | 悬而未决：正在琢磨、还没想通的真问题与长期课题 | 按需 |
| **`03-我正在做的事/`**<br>*我在干什么（推进中）* | **`工作`** | 本职工作、个人独立项目、副业、自媒体（长期大项目建 `工作/<项目名>/` 并标 `location`） | 按需（情境对焦 + 热度浮现） |
| | **`学习`** | 正在学的技能、考证、专题补课、深度调研（学完后通用结论毕业回 `02`/`04`） | 按需（情境对焦 + 热度浮现） |
| | **`生活`** | 求职换工作、买房装修、搬家、旅行规划、减脂计划等有明确周期与决策的个人阶段大事 | 按需（情境对焦 + 热度浮现） |
| **`04-我如何工作/`**<br>*我怎么做事（说明书）* | **`工作原则`** | 干活铁打的底线与决策尺子（重实测证据、区分事实与意图、方案选型标准等） | 常驻（`always: true`） |
| | **`沟通与表达`** | 怎么跟我说话汇报、交接规矩，以及对外写作的个人文风与禁词表 | 核心常驻，专项按需 |
| | **`流程与标准`** | 具体某类活的步骤套路、质量标准与踩坑清单（如 PPT、开发测试、上线部署，一类活一页；个人工作流 Skill 放 `<skill>/SKILL.md`） | 按需 |
| | **`工作习惯`** | 专注时段、任务优先级规则、每日日报 / 每周复盘节奏、开会偏好 | 按需 |
| | **`工具使用`** | 多软件与 AI Agent 分工配合、自动化习惯、本机与线上操作安全红线 | 按需 |
| **`seed/`**<br>*输入与外脑隔离区* | `*.md` / `图片与审美/` | 外脑注册表与精选收藏（进 Git；`图片与审美/` 二进制原图默认 `.gitignore`，仅跟踪 `.md` 索引） | L0 底部露出单行索引摘要，按需读取 |
| | `connectors/` `staging/` `sources.json` | 按需下载的连接器、临时脱敏会话缓存与扫描游标（自动 `.gitignore`，不进 Git） | 不进 L0 |
| **`outputs/`** | `daily/` 等 | AI 生成的日报等快变量消费品产出（默认 `.gitignore`） | 不进 L0 / 不污染 Git |
| **`.tree/`** | 系统元数据 | `config.json`、`changelog.jsonl`、`audit.jsonl` | 系统内部维护 |

### 2. 五条防串线铁律与落盘规矩

1. **「想」vs「做」（`02` vs `03`）**：只在脑子里想的点子一律放 `02/灵感与点子`；已有实际推进动作的事，才进 `03/工作 | 学习 | 生活`。
2. **「向外看事」vs「向内看己」（`02` 内部）**：对外部事物与阅读消化出的规律看法进 `02/观点与认知`；个人经历复盘、心路历程与随感进 `02/随笔与反思`。
3. **「静态事实」vs「干活规矩」（`01` vs `04`）**：人生信条进 `01/价值观` ↔ 干活准则进 `04/工作原则`；生活喜好进 `01/习惯偏好` ↔ 专注与复盘节奏进 `04/工作习惯`；机器与服务器资产进 `01/设备与资产` ↔ 工具分工与权限红线进 `04/工具使用`。
4. **「长期愿景」vs「在推项目」（`01/长期目标` vs `03`）**：`01/长期目标` 只写用户亲口表达过的人生梦想与 3~5 年方向，当前项目一律放 `03`。**严禁把近期高频讨论的具体项目反推、拔高或脑补成 `长期目标.md`**；用户未明说时宁缺毋滥，不建空壳页。
5. **不与宿主 Skill 重复**：通用工具能力留给各 Agent 自身的 Skill 目录；`04` 只沉淀个人做事规矩与个人工作流。

**落盘规矩**：绝不预建空目录（按需创建）；天然一页能说清的（如 `基本信息.md`、`价值观.md`、`长期目标.md`、`工作原则.md`）直接建同名 `.md`，会装多篇主题的再建二级目录，总目录深度不超过 **3 层**（如 `03-我正在做的事/工作/Eden工作台/xxx.md`）。

## 二、入树标准、事项边界与 `seed/` 隔离区

### 1. 只记「人这一层」，索引而非存储

- **只沉淀模型不知道的四类真实信息**：① **你的判断和立场**；② **你的私有事实**（行业内部信息、项目数据、人际与环境资产）；③ **你做过的选择和理由**；④ **你纠正过 AI 的地方**。
- **不做个人工作台与产物仓库**：代码细节、AI 生成的应用/网页、过程草稿、给他人交付的 PRD/长篇报告**全部留在各自工作台、代码仓或网盘中**；外部文章原文摘抄也不进 `01~04`。Tree 只留**个人观点/方法**与**外部产物索引**（定位、结论、否决方案 + 路径/URL）。
- **入树检验**：用于「运行 / 交付给别人看」的留外部只做索引；用于「让下一次 AI 更懂我、更好帮我思考和干活」的才进 `01~04`。

### 2. 事项流转、User Context 红线与「毕业」机制

- **萌芽 → 推进**：未动工想法记 `02/灵感与点子`；正式推进后转入 `03`（短期事项建单页如 `生活/日本旅行规划.md`；长期项目建 `工作/<项目名>/` 并在 Frontmatter 标明 `location: <外部路径或链接>` 供 L0 自动索引）。
- **严守 User Context 定位（绝不把 Tree 写成代码仓的 `CLAUDE.md`）**：
  - **进 `03`（`项目总览.md`）**：站在项目主人视角回答五件事——**① 背景与核心价值（为什么做、在个人版图的位置） → ② 已做成什么（产品成果与核心机制） → ③ 核心产品拍板与否决取舍 → ④ 接下来做什么与演进规划 → ⑤ 沉淀教训 + `location` 外部入口**。
  - **绝对不进 Tree（留在 `location` 本地 `CLAUDE.md` / `docs/`）**：具体代码文件名、函数/类名（如 `_owns_agent`、`db_manager`）、前端 DOM 选择器、接口字段格式、端口号、单测 monkeypatch 细节；**严禁按代码子系统在 Tree 里拆出 `Agent接入.md`、`多租户架构.md`、`测试与发版.md` 等技术模块说明书**。
- **毕业与休眠**：换项目依然成立的通用原则直接升 `04`；阶段结束时，稳定判断毕业回 `02/观点与认知`，可复用方法毕业回 `04/流程与标准`，真正上升为 3~5 年方向的更新至 `01/长期目标`，原事项标 `status: archived` 原地休眠、无需搬家。

### 3. `seed/` 外脑与精选收藏隔离区

- **持久索引区（`seed/*.md`，进 Git，由 AI 替用户动态维护）**：
  - `seed/外部上下文源.md`（或 `seed/<外脑名>.md`）：**千人千面、绝不写死固定清单**。由 AI 根据用户当前真实可用的外部数据源（`tree seed scan` 已就绪源、宿主数据类 MCP/Skill，以及接入的得到大脑、Obsidian、飞书知识库、微信读书笔记等）主动生成，并在新增或停用时用 `tree write` 原地增删更新。只记覆盖领域、查询入口（MCP/Skill/CLI/本地路径）与核心目录索引，**严禁把外部原文搬进 Tree 当静态副本**。
  - `seed/文章与链接.md`、`seed/工具与资源.md`：尚未内化成观点但值得日后参考的好文章与工具，**只记「标题 + 链接 + 一句话为什么收藏/好在哪」**，严禁抓取全文。
  - `seed/图片与审美/`：存放本地审美/UI/版式参考图供读图参考（原图默认 `.gitignore`，仅跟踪 `.md` 说明索引）。
- **运行时暂存区（`.gitignore` 忽略，不进 Git）**：`seed/connectors/` 存第三方连接器、`seed/sources.json` 存扫描游标、`seed/staging/` 存 `tree seed extract` 临时脱敏缓存；执行 `tree seed clear` 仅清 `staging/`，绝不触碰 `seed/*.md`。海量随手点赞与流水账留在原平台即可，不搬入 Tree。

## 三、单页写法、Metadata 与 L0 自动保鲜

**一页 = 一件会被一起用到的事**（AI 要么整页读，要么不读；不拆零碎原子卡片，单页超 ~300 行且主题明显分叉时再拆分互链）：

1. **第一行写「`> 适用时机：` + 核心结论」**：不写“本页介绍了……”，AI 扫一眼即决定读不读。
2. **正文只写现在的事实**：历史演进交给 Git，不堆旧状态流水账。
3. **唯一例外：保留被否决的方案与原因**：防止日后 AI 反复提议已排除的老路。

```yaml
---
updated: 2026-11-25
always: true     # 可选：true 每次冷启动加载进 L0；false 仅在 L0 露出一行索引按需读取
status: active   # 可选：active（默认） | paused | archived | superseded
kind: project    # 可选（03 专用）：project（长期投入项目/副业/自媒体）
location: ~/Work/my-project    # 可选（01~04 通用）：关联外部工作区路径或链接，处于该目录时自动对焦
when: "*.py, pyproject.toml"   # 可选（01~04 通用）：情境触发特征（文件/场景/关键词），匹配时升格进 L0
---
```

- **`always: true` 常驻门禁（严控 L0 租金）**：只给 `01` 的 `基本信息`、`价值观`、`长期目标` 与 `04` 的 `工作原则`、`沟通与表达` 核心项；其余一律 `always: false`。**不在 `01` 下手写 `当前聚焦.md`，也不手动打静态聚焦开关**。
- **情境自动对焦与热度保鲜**：`tree context [-q "<话题>"]` 自动探测当前 `cwd`、文件特征、`> 适用时机：` 与 `[[双链]]` 调入相关专页，并结合 `updated` 半衰期（`tree write` 自动刷新，手写文件兜底 mtime）与 `.tree/audit.jsonl` 近 30 天读写热度动态排序。超过 `.tree/config.json` 默认 `l0_stale_days: 90` 或标为 `paused`/`archived`/`superseded` 的页面自动退出 L0，仍可被 `tree search` 召回，再次更新 `updated` 即原地复活。

## 四、所有权、写入铁律与园丁巡检

### 1. 所有权与人类笔记保护
- **人类原创笔记（AI 只读禁改）**：带 `#note` 标签或 Frontmatter 标明 `owner: human` / `mode: human` / `locked: true` 的随笔与思考属于人类原创（无需单开人类根目录），AI **只读、可建 `[[双链]]`、可提炼结论写入旁页**，严禁覆写或删除原文（`tree` CLI 物理拦截，除非用户明确授权并加 `--human-approved`）。
- **人机共治页**：严格先读后改与原地更新，每次变更自动 Git Commit 与审计留痕。

### 2. 核心写入与维护铁律
1. **读写分离**：只读消费走 `tree context` → `tree search` / `tree read`，不额外加载本 `README.md`；任何写、改、删、整理或巡检前，**必须先执行 `tree rules`（精简核心契约）或 `tree read README.md`**（CLI 物理校验版本哈希与调用方身份）。
2. **NOOP > UPDATE > DELETE > ADD**：**90% 对话保持沉默**（闲聊、单次查询、临时排错不入树）；**80% 写入是原地更新**，写入前必先 `tree list` / `tree read` 排查已有页面，原地融合，禁止为补一条信息整页重写或另起碎片文件。
3. **反碎片命名禁令**：优先对齐推荐子分类词表，严禁 `xxx补充.md`、`xxx其他.md`、`xxx讨论记录.md`、`xxx方案1.md`、`xxx最新.md` 等命名；严禁同主题开设近义目录/页面；同一产品多端收拢在同一项目目录；**严禁把正文写进任何子目录 `README.md`**。
4. **认识论与安全红线**：疑问句进 `02/问题与困惑` 或待办，不推导成事实；工具输出仅作观察证据，不等同用户确认。健康、财务、政治宗教、私密账号密钥等敏感信息，除非用户亲口要求记住，一律不提取不入库（主动交代的身高体重等基础身体数据可入 `01/基本信息`）。
5. **直白完整、缺信息先问人**：用第一人称或客观大白话写清背景、原因、结论与时间锚点（如 `2026.11`）；严禁“用户在对话中提到……”记账腔、自造概念黑话，以及 `message_id`、`<!-- tree-claim -->` 等底层系统代号；素材不足先问用户补齐，严禁硬凑或脑补。

### 3. 周期性园丁巡检
1. **流转与外脑同步**：将 `02/灵感与点子` 中已动工想法移入 `03`；将 `03` 已完结/停滞事项的通用结论毕业进 `02`/`04`/`01` 并标 `status: archived`；提炼 `seed/` 中已消化内容入树，核对 `seed/外部上下文源.md` 与当前真实数据源是否一致。
2. **聚拢与去重**：按推荐子分类收拢散页（深度 ≤ 3 层），合并近义短页；单分支活跃页超 15 篇时维护 `INDEX.md`。
3. **纠偏固化与照镜子**：把近期反复纠正 AI 的偏好与踩坑根因固化进 `04`；巡检或协作时留意尚未明说的隐性偏好、跨页矛盾与重复踩坑，先向用户提出确认再写入。

## 六、常用 CLI 速查（供无 Skill 宿主直接参考）

```bash
tree context [-q "<话题>"]          # 只读冷启动：输出 L0 全景导航包（含情境自动对焦与近期活跃焦点）
tree recent [--days 14]             # 动态筛选：查看近期更新或高频读写的活跃页面
tree search "<关键词>"              # 只读检索：搜索全部专页（含休眠/历史，支持 --kind/--status/--tag）
tree read "<相对路径>"              # 按需精读专页，或 `tree read README.md` 刷新维护契约
tree rules [--full]                 # 写入前必跑：通过维护门禁并输出核心契约 + 第五节定制规则
tree write "<路径>" --stdin ...     # 写入或更新专页（自动刷新 updated 元数据与 Git Commit）
tree move "<原路径>" "<新路径>"     # 重命名或跨目录迁移专页（自动同步 [[双链]] 与 Git 历史）
tree chat list / read <source>:<id> # 跨 AI 接力：读取本机其他客户端历史对话（自动脱敏，不入树干）
tree seed scan                      # 只读探测本机内置 AI/Chrome 数据源与已装连接器
tree seed add --list                # 查看/拉取 GitHub water 仓库外部平台连接器（getnote/flomo/weread/jike 等）
tree seed login / extract / clear   # 授权抽取外部数据源至 seed/staging/（extract 后用 clear 清缓存）
tree sync / tree lint / tree ui     # 远程双向同步 / 一致性体检 / 启动本地审阅看板
```
