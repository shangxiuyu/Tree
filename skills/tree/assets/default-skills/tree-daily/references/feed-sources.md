# Tree Daily 多源采集与通用 Feed 路由指南（V2）

> 适用所有职业与地区用户，不预设单一行业或特定本机 App。核心原则：**工作·学习·生活三维度实证盘点 + 按用户 Tree 动态选源 + 实读一手内容 + 质量不达标直接熔断**。

---

## 一、如何盘点用户的「工作 · 学习 · 生活」每日轨迹

在写 `## 昨日复盘`（昨天 `00:00–24:00`）和 `## 今日记录`（今天 `00:00` 截至当前）时，从本机已有工具和记录里分三路提取事实，**有什么写什么，不编造、不说教**：

| 维度 | 采集来源（按宿主实际可用工具） | 提炼重点 |
| :--- | :--- | :--- |
| **工作** | `tree recent`、`vault` 与活跃项目 `location` 仓库 `git log`、`tree chat list/read` 中的开发/写文档/定方案会话 | 具体推进了哪几个项目、拍板了什么产品/工程决策、清理了什么技术债、还卡在哪 |
| **学习** | `tree chat` 中的竞品拆解/技术原理探讨、社区/外脑最新收藏、`seed/` 目录新增外脑与收藏、浏览器近期书签 | 调研了什么外部架构（如 Supermemory / 上下文暴露）、收藏或消化了哪篇行业长文/播客、得出了什么判断 |
| **生活** | 全天首次与末次跨端会话时间戳（作息跨度）、`03-我正在做的事/生活/`、本机已挂载的生活工具（生鲜/外卖/电商/运动等近期记录） | 作息起止时段（如 `09:02–16:54`，晚间有无熬夜加班）、当日采购/饮食或运动记录、常购日用品周期余量（客观摆事实与天数，严禁家长式说教与隐私订单号/金额裸露） |

## 二、如何从用户 Tree 动态拆出 3 组 Feed 检索维度

拿到 `tree context` 和近期焦点后，**不要把全部检索都砸向用户最近 2 小时聊的单一项目**，必须拆成 3 个桶来找源：

| 维度桶 | 当日配额 | 选品目标 |
| :--- | :--- | :--- |
| **桶 A：手头主线项目（来自项目分支）** | **最多 2 条** | 至少 1 条必须是**反方冷水、前辈翻车复盘、或竞品做得更好的具体工程/产品细节**；严禁只找吹捧材料。 |
| **桶 B：长期关切与职业方法（来自个人画像 / 思考分支）** | **至少 2 条** | 覆盖用户当前阶段真正在意但今天没聊的议题（职业选择、变现路径、专业评测、管理、写作等），打破局部视野。 |
| **桶 C：跨界高信号或深度长文** | **0~2 条** | 挑一篇真正经得起读的行业深度访谈、论文拆解或跨领域案例，保持每天的新鲜感。 |

> **时效配额底线**：常规日更中，至少 **1~2 条**优先取近 7 天内新发布的动态/项目/讨论；允许推往年常青经典好文或成熟工具，但必须在标题里注明年份（如 `（2025）`），避免连发 7 天退化成“经典老书单”。

## 三、两层信息源策略

### 第一层：按用户画像与语言偏好动态组合常用源
不要对所有用户都默认把 GitHub 排第一。先看用户的语言环境与背景，从下列源中选 3~5 个组合：
- **中文深度社区与播客**：小宇宙（有 MCP 时**必须调用详情接口读完 ShowNotes 再决定推不推**，过滤播放量极低或时间轴明显造假的 AI 水播客）、即刻、少数派、知乎、B站、小红书/公众号精选；
- **全球技术与产品一手源**：GitHub（推仓库必须给清 Star/定位/可抄的具体机制，不复述 README 第一句）、X (Twitter) 核心作者、Hacker News、Product Hunt、Substack / 独立作者长文博客、YouTube 访谈；
- **学术与行业报告**：arXiv、Google Scholar、顶级实验室工程博客（如 Anthropic / OpenAI / DeepMind / Vercel 等）、行业研报。

### 第二层：按职业自动追加垂直源示例

| 用户职业 / 关注方向 | 自动推导的高信号垂直源 |
| :--- | :--- |
| **AI / 软件产品经理与工程师** | Anthropic / OpenAI / LangChain 工程博客、Hamel Husain / Lenny's Newsletter、Hacker News、GitHub、十字路口 / 42章经等一线访谈播客 |
| **独立开发者 / 创作者 / 副业变现** | Indie Hackers、Product Hunt、少数派、生财有术（若已挂载）、真实收入复盘独立博客 |
| **设计 / 品牌 / 交互** | Linear / Raycast / Figma Blog、Awwwards、Mobbin、设计师独立通讯 |
| **商业 / 消费 / 投资研究** | 晚点 LatePost、Stratechery、a16z、Acquired 播客、财报与行业一手研报 |
| **医疗 / 法律 / 教育 / 科研等非科技职业** | 对应领域权威期刊、垂直行业协会/媒体、高质量中文/英文专业播客与实务案例库 |

## 四、质量熔断与链接诚实原则

1. **拿不到单篇直链就丢弃**：如果某次搜索只返回泛泛的“话题汇总摘要”，既没给出具体文章/视频 URL、也没给出作者和具体案例，**直接淘汰这条**，不要在日报里写“建议你去某站搜某词”。
2. **必须读到真干货才写**：播客要看真实 ShowNotes（顺手瞄一眼评论区有没有避坑点，如口音/音质/中英夹杂）；博客要提取具体数字、实验结论或方法步骤；GitHub 要拆出具体机制对比。
3. **跨天防重**：落盘前对照 `tree daily recent-feeds --days 14`，14 天内推过的 URL 绝不重复上榜。
