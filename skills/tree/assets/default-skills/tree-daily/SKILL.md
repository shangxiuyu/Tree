# Tree Daily — 每日一份私人总编日报 Skill

本 Skill 位于你的 `04-我如何工作/tree-daily/`，是**唯一真源**：通用流程和你的个人定制要求都在这一份文件里。想加新板块（如“今日吃什么”）、换信息源或调语气，直接修改文末「四、我的个人定制」即可，无需改多处文件。

核心原则：**每天只维护 1 份完整日报（早间出刊复盘昨日、日内/晚间随时补录今日所做，工作·学习·生活三维度全景梳理不漏项）；你管品味、配额与说人话，`tree daily write` CLI 管格式契约、同日唯一、14 天去重和隐私防泄。**

## 一、日报结构（与 Tree `03` 工作·学习·生活同构）

1. **`## 昨日复盘`**（必填，**必须按「工作 / 学习 / 生活」三维度全景梳理**）：
   - `- **工作**：` 昨天 `00:00–24:00` 实际推进了哪些项目、做了什么拍板、解决了什么问题（数据来自 `tree recent`、代码仓/知识库 `git log`、跨端 AI 对话 `tree chat`）。
   - `- **学习**：` 昨天输入了什么新知识、调研拆解了什么竞品/技术方案、阅读或收藏了什么有启发的内容（数据来自跨端 AI 探讨会话、社区/外脑最新收藏、`seed/` 目录新增外脑/收藏、浏览器近期书签/阅读记录）。
   - `- **生活**：` 昨天日常饮食/采购、运动健康、作息活跃起止时段与生活事项推进（数据来自本机生鲜/外卖/电商/运动工具、`03/生活/` 及全天跨端活跃时间戳；**日常客观记录事实，不隐藏、不说教**；若触发周期补货前 1~2 天或连续熬夜等信号，顺手在生活条末尾附一句客观提醒）。
   - `- **卡点与未决**：`（可选）昨天还没拍板或未闭环的事项。
2. **`## 今日记录`**（**日内/晚间刷新时出现**，同样按 **`工作 / 学习 / 生活`** 三维度梳理）：
   - 早间首次生成且当天尚无新动作时可省略；
   - **当用户在白天或晚上查看、刷新日报或要求“复盘今天”时，必须生成/更新本板块**，如实梳理**今天 `00:00` 截至当前时刻**用户在**工作、学习、生活**上已经做了什么，并同步勾选 `## 今日聚焦` 中已完成的条目。
3. **`## 候选沉淀`**（必填，0~2 条）：从昨天或今天已发生的事里挑出值得长期记住的慢变量，标明建议动作与归属文件；没达到慢变量标准写 `今日无须入树`。**未经用户确认，严禁直接修改 `01~04`。**
4. **`## 今日聚焦`**（必填，1~3 件）：从尚未闭环的事和 Tree 聚焦项目自然长出来，说清背景与完成标准。
5. **`## 今日专属 Feed`**（必填，3~6 条；纯离线无搜索设 `feed_count: 0` 可省略）：基于 Tree 画像策展的有限信息流，刷完即止。
6. **`## 顺手清一篇旧藏`**（**可选，0~1 条**）：不占主 Feed 坑位；仅当你真读透用户收藏夹里的某篇原文并挖出具体盲区/数据时才放，否则省略。
7. **`## 明日预热`**（**可选**）：仅当明天有明确日程、截止日或需提前准备的跨天事项时才出现，否则省略。
8. **`## <个人自定义板块>`**（**见文末「四、我的个人定制」**）：固定 H2 标题且不含动态时间，天然通过校验并可被前端通用卡片渲染。

- **状态字段**：Frontmatter 仅用 `status: ready`（出刊定稿）或 `status: reviewed`（已审阅勾选）。
- **严禁使用 `tree write` 写日报**：`outputs/` 独立于 `01~04` 且默认被 `.gitignore` 忽略。所有日报落盘必须走 `tree daily write --date <YYYY-MM-DD> --theme "<主题>" --stdin`。
- **同日动态刷新**：早间出刊后，当天任何时刻用户再次查看或要求更新日报时，保持同一份当天日报（`tree daily write` 自动原子覆盖同日文件），补齐/刷新 `## 今日记录` 的工作、学习、生活进展，无需拆出第二份晚报文件。

## 二、执行流程（4 步）

### Step 1：先读人与历史（全量盘点昨日 + 今日的工作/学习/生活轨迹）
```bash
tree context                                                 # 读用户画像、沟通底线与当前聚焦
tree recent --days 7                                         # 看近 7 天所思所做
tree chat list --limit 20                                    # 盘点昨天与今天跨端 AI 会话（区分工作干活 vs 学习调研 + 提取起止作息时间）
tree daily latest --before <今日 YYYY-MM-DD>                  # 读上一期日报（承接聚焦与未决项）
tree daily recent-feeds --days 14 --exclude-date <今日>       # 获取近 14 天已推 URL 去重指纹
```
- **空树冷启动**：若 `tree context` 返回 `[SEED_STATE: 幼苗未破土]`，先问用户 2 个问题（身份与最关注的 1~2 个主题），不盲推热搜。
- **把本机线索分拣进「工作 / 学习 / 生活」三个篮子**：
  - **工作篮**：`tree recent`、`vault` 与活跃项目 `location` 仓库的 `git log --since`、`tree chat` 中写代码/改文档/定方案的会话；
  - **学习篮**：`tree chat` 中读源码/拆竞品/问原理的会话、社区/外脑最新收藏、`seed/` 目录新增外脑索引与精选收藏、浏览器近期书签；
  - **生活篮**：全天首次与末次对话时间戳（作息跨度）、`03-我正在做的事/生活/`、本机已挂载的生活工具（生鲜/外卖/电商/运动等近期订单与运动记录）。若某维度当天确实无本地记录，实事求是写清已观测到的部分（如作息活跃时段与补货周期状态），**严禁脑补未发生的生活细节**。
- 必须遵守用户在 `04-我如何工作/` 写下的全局沟通与写作底线。

### Step 2：能力自发现 & 并行采样
扫描当前宿主实际挂载的搜索、社区、播客、代码或生活工具，按 [references/feed-sources.md](references/feed-sources.md) 采样：
- **纯离线降级**：既无联网搜索也无外部工具时，设 `feed_count: 0` 只写复盘、今日记录与聚焦，**严禁凭记忆编造文章和假 URL**。
- **异常静默降级**：单源报 401/超时直接跳过并记入 Frontmatter `sources_skipped`（如 `"jike-search:401"`）；**只在需要用户修凭证时**于文末 `---` 下留 1 行 `> ⚠️ ...`，不要在正文多处重复提同一报错。

### Step 3：选品淘汰阀（5 道硬闸门，宁缺毋滥）
拟推内容必须全部通过以下 5 关，任一不通过**立刻删掉**（宁发 3 条硬货，绝不发 6 条掺水货）：
1. **跨维度 + 时效双配额**（主 Feed 3~6 条）：
   - 当前单一项目 / 昨天话题**最多占 2 条**，且至少 1 条必须是**反方冷水、前辈翻车复盘或竞品具体实招**；
   - **至少 2 条**覆盖用户画像里的**其他长期关切**（职业决策、商业变现、专业方法论、跨界视野等）；
   - 常规日更至少 **1~2 条**优先取近 7 天新动态/新项目；推往年经典好文/老工具须在标题标明年份（如 `（经典 · 2025）`）。
2. **实读与直链熔断**：必须有真实可点击的 `[名称](https://...)` 单篇直链，且读到一手内容（正文、ShowNotes、仓库细节或实验数据），**绝不拿转发语充数，绝不甩搜索词凑数**。
3. **14 天去重 & 旧藏隔离**：命中 `recent-feeds` 的 URL 直接淘汰；旧藏不占主 Feed 坑位且同样受 14 天去重约束。
4. **工作·学习·生活客观记录（去说教）**：`## 昨日复盘` 与 `## 今日记录` 中的 `- **生活**：` 始终客观呈现作息跨度、采购/饮食、运动或生活事项进展，不凭单一 App 订单说教营养，不下家长式指令。
5. **去复读 & 决策标签**：同一件事全文只说一次；每条 Feed 必须给 `[必看原文]` / `[看这3句就行]` / `[只听片段 XX:XX]` 标签。

### Step 4：校验落盘
参照 [references/daily-template.md](references/daily-template.md) 生成 Markdown，经隔离通道写入（未通过校验会被拦截，修正至 0 error）：
```bash
cat <<'EOF' | tree daily write --date <YYYY-MM-DD> --theme "<4~12字核心主题>" --stdin
...
EOF
```

## 三、文风正反例（写前扫一眼，避开 90% 的 AI 味）

| 雷区 | ❌ 绝对禁止（反例） | ✅ 正确写法（正例） |
| :--- | :--- | :--- |
| **只记写代码漏掉学习与生活** | `## 昨日复盘` 只有一条“昨天改了 3 个脚本”，学习与生活只字不提。 | 按 `- **工作**：` `- **学习**：` `- **生活**：` 三条完整梳理昨天的项目拍板、竞品/长文输入与作息采购状态。 |
| **拍马屁附和** | “恰好印证了你的方向，几乎给出官方学术背书。” | “原文实验数据正好反驳你现在的做法：413 个文件输给 9 个文件，过度写死规矩会让强模型变笨。” |
| **自造黑话** | “收束出跨目录特征嗅探方案，构建每日消费层的选题母体。” | “昨天定了按当前目录自动挑上下文的思路，先用日报跑通每天看一遍的习惯。” |
| **妈味说教** | “距上次下单已过 5 天，近十天少绿叶菜，晚饭带份青菜；晚上早点收尾。” | “昨天本机活跃时段 09:02–16:54（晚间无加班会话）；叮咚上次补货在 11-20（可乐与土香鸡块），按 11 天周期余量充足。” |
| **硬凑水贴** | “本次搜索仅返回聚合摘要，建议去某站搜 XXX。” | *(直接熔断删除，今天发 4 条真硬货)* |
| **重复报错** | 在复盘、聚焦、告警里把 401 报错念三遍。 | 统计留 Frontmatter；正文只在文末 `---` 下留 1 行 `> ⚠️ ...`。 |

> **落盘硬校验要点（`tree daily write` 自动拦截）**：Frontmatter `theme` 须与 `--theme` 一致且 `sources_ok` 不可为空；须含 `## 昨日复盘`、`## 候选沉淀`、`## 今日聚焦`；固定 H2 标题内不得含 `HH:MM` 时间戳；每张 Feed 卡片须为 `### 1. [来源] 标题` 且含 `- **结论标签**：[必看原文]` / `[看这3句就行]` / `[只听片段 mm:ss]`、`- **关联**：`、`- **要点**：`、`- **链接**：[名称](https://...)`；`## 候选沉淀` 须为 `- [ ] \`create|update|append\` \`路径.md\` — 理由` 或 `- 今日无须入树`；严禁出现 `## 采集说明`、长数字单号或明文密钥。
